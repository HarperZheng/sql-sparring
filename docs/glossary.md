# 术语表（glossary）

> 规则（CLAUDE.md【术语纪律】）：新术语先登记本表再使用；每条 ≤2 句，"是什么 + 在本项目指什么"。

- **payload（原始报文）**：程序运行时逐条输出的原始消息流，一字不改存档，是一级证据。本项目指 datus 每答一题的完整 agent 循环输出，M0 起每题活跑落 `rounds/<轮>/runs/datus/`。
- **幂等**：同一操作重复执行，结果不变、无副作用。本项目指适配器支持 `--only qNN` 子集复跑且不污染已有留痕。
- **headless（无头）**：无交互界面的命令行调用方式。本项目用：datus chat API（:8501 SSE 流）、`claude -p`、`POST :4100/chat`（v0 另用 `datus -p`，已退役）。
- **盲考**：出题人不读答题人侧任何产出、不读历史题库，只读考纲出题（决策 D3）。
- **三态**：cube `POST :4100/chat` 返回的三种类型：`answer`（有答案）/ `ask`（反问口径）/ `nomatch`（能力外）。
- **作答卡**：每题每方的机器提取结果（统一结构），从原始留痕提取而来。M0 最小结构 11 字段，M1 升格为 JSON Schema。
- **语义层**：智能体把自然语言映射到 SQL 所依赖的建模层。datus 侧=dosi YAML（`fne_fund_main.yml`），cube 侧=Cube schema + 词典。
- **对接**：把本仓适配器与真实智能体服务连起来调通，完成一次"问→答→留痕→提取"端到端。本项目 M0 的主目标：datus 与 cube 各自证明"可调用、能答数"。
- **活体验证**：真实调用正在运行的智能体服务、用新题做验证，不引用任何历史存档当依据。本项目指新题真打 datus chat API / `:4100/chat`。
- **拍板政策**：使用者对智能体口径反问的标准应答规则。本项目 M0 自动化版=取第一个选项原文回发同一会话（"就按第一个选项的口径来……"），追问与选项记录在作答卡 arbiter 字段。
- **锚点**：用来核对的已知基准值。本项目指 cube regress `run_yoy.py` 的比对数字（查询层回归）。
- **WSL 桥接**：Windows 侧程序经 `wsl.exe` 调用 WSL 内命令、以文件交接数据的方式。本项目 ask_datus v0 用它跑 `datus -p`，2026-10-23 起被 chat API 替代（`wsl_runner.py` 保留作回退参考）。
- **chat API（datus）**：datus --web 常驻服务的 HTTP 接口，本项目指 `:8501` 的 `POST /api/v1/chat/stream`（SSE 流，与 UI 同源；agent 配置/语义模型只在服务启动时装一次）。ask_datus 2026-10-23 起的正式作答通道。
- **轮（round）**：一次完整的"出题→双侧作答→裁决→回改"流程及其归档目录。本项目正式自动轮从 round-02 起放 `rounds/`；m0 是里程碑 M0 的验证轮。
- **v0（第零轮）**：本仓写代码之前的纯人工实测（约 2026-09~10），datus 25 题 + cube 30 题。记录留存于 datus 仓 `development_process_record/non_tax/`（07/09/10 号文档）。
- **模型配置（conf/models.json）**：出题人与裁判的模型/接口/key 引用集中放这一个配置文件，换模型换接口只改配置不改代码。key 不入库，配置只存环境变量名（本仓已公开于 GitHub），真实 key 放本机环境变量。
- **契约（schemas/）**：角色之间交接数据的固定格式，M1 冻结为 schemas/ 下三份 JSON Schema + 校验器；组件只按契约交换数据，不许私改字段。
- **JSON Schema**：给 JSON 数据写"验收单"的标准格式，声明哪些字段必填、允许取什么值；本仓用 jsonschema 库逐份校验。
- **口径卡**：一方对某题"怎么算的"归一化陈述（用什么指标、什么时间轴、什么去重键）。M1 拍板：只在裁决书 cards，作答卡不设。
- **裁决书（verdict）**：裁判逐题产出的双侧口径卡对照 + 逐指标比对 + 四态结论，落 `rounds/<轮>/verdicts/`。
- **四态**：裁决结论的四种取值：互证通过 / 建模差异 / 执行事故 / 待人工。
- **考纲（syllabus/）**：出题唯一依据 = `syllabus/` 目录自包含两件：原始资料 `bussiness/` + 业务课本 `business.md`（M2 建，决策 D11 不读数据项与数据源）；题库 syllabus_ref 指向课本的知识点编号。
- **原始资料**：业务方文档原件，原样存档不改，是课本的出处；指 `syllabus/bussiness/`（非税收入收缴业务说明等）。出题人不读它，出题人唯一读物是课本。
- **业务课本**：`syllabus/business.md`，从原始资料收编业务知识（剥离表定义/字段名/数据可得性，决策 D11）、加知识点编号的出题人唯一读物，含"已裁定口径"递增章节。
- **知识点编号**：课本小节编号（B01…），题库 syllabus_ref 指向它，可追溯每题考的什么。
- **剥题纪律**：课本只放业务知识与事实，不放历史题库原题文本与答案式数值，防止出题人抄题。
- **已裁定口径**：课本的递增章节，收录历轮裁决书裁定的口径结论，轮次间滚动补充，教材随互搏生长。
- **覆盖矩阵**：考纲知识点 × 题型的核对表，检查漏覆盖知识点与题型配比是否达标。
- **悬空检查**：题库 syllabus_ref 指向的编号在课本中不存在的检查，悬空即判废。
- **出题人四件套**：M2 四组件总称：业务课本 + examiner/SKILL.md + bin/examine.py + bin/preflight.py。
- **健康检查**：`bin/preflight.py`，开跑前的单次连通性断言（双侧服务可达、语义层文件可解析）；不进轮循环、不留档、不落作答卡。
- **冒烟试答**：M2 收尾从题库抽少量题真发两侧，只验证题库能被适配器消费并出卡，不算正式作答、不裁决。
- **轮驱动器**：`bin/round.py`（M3 建），读题库、逐题调两适配器、收作答卡的串联循环，即答题人的"调派者"。
- **校验器（bin/validate.py）**：把题库/作答卡/裁决书逐份对 JSON Schema 检查的脚本，不过即逐条报错退出；适配器写卡前也内联校验。
- **执行记录取证**：SQL 证据机制（v4，2026-10-23）——query_metrics 返回体不含 SQL（datus 工具层防 LLM 上下文膨胀而剥离），实际执行原文由 datus 侧日志（`dosi_sql_executed` 行）留痕，`adapters/ask_datus/evidence.py` 按题时间窗提取进作答卡；旁路观测，LLM 无感知、作答行为零扰动。
- **AI初步裁决**：裁决阶段的草稿环节（M3-3）——AI 助手逐题读双侧作答卡、按 D4 先口径后数值、按 D12 定四态，产出 `verdicts/qNN.json` 草稿供用户抽查修正，抽查后才算定稿（v1 人工在环）。
- **问题单**：裁决书里"谁动手、动什么、怎么修"的结构化条目（side/type/target/suggest），落 `verdict_detail` 数组；回改①的智能体据它起草回改单主表与回改卡，非空题默认进下轮复验集（D12）。
- **回改**：分歧从裁决走向语义层真正修好的固定流程，五步：①查证起草（智能体）→②审定（人）→③施工（人）→④复验（系统）→⑤闭环入库（人）；"回灌"的定名（2026-10-26 定稿），以后一律叫回改。
- **回改单（feedback.md）**：每轮一份的回改工作文档 `rounds/<轮>/feedback.md`：文件头（契约+状态机+冲突规则+全局拍板）+主表（id/问题/修改对象/拍板结论/状态）+回改卡；由回改①的智能体创建（人看过轮报后调起，codeqa 逐题查证写入），不是 round.py 产物。
- **回改卡**：回改单主表下每题一节的施工说明：证据/双侧改法/前置验证/记忆清理/验收。
- **行状态机**：回改单主表每行的状态流转：待查证→草案→已审定→已施工→闭环；④复验挂了回③、口径错回①；终态另有剔除（本轮不做的题，不进五步与闭环统计）。
- **审定**：回改②，人逐行审定智能体起草的拍板结论与双侧改法；通过才允许施工。
- **闭环入库**：回改⑤，复验通过且人工确认后，把该题拍板结论经 `round.py suite-add` 读闭环行写入 `suite/accepted_answers.json`；行状态转闭环。
- **真实字段解法**：回改①用 codeqa 在生产源代码里查证出的某题正确口径：过滤器+指标+维度+时间锚（落库表真实字段，非语义层现名）。
- **时间锚**：口径取数依据的时间字段（如缴款 fdate、缴库 fenterdate），精度统一 toDate（只到日期）。
